# BEAT ON STAGE キャラ受付・制作・管理フロー

2026-10-29／運用設計 v1.0。手順を整理した資料であり、登録機能や管理画面は未実装。

## 基本方針

管理しやすい・作りやすい・ゲームに合うことを優先する。キャラごとの特別なコードや専用リンクは作らず、同じサイトの一覧から選ぶ。基本はゆずちゃん。出場者に限らず応援参加者・創作キャラも受け付ける。キャラによる得点・判定の差は設けない。

標準デザインはユーザーが確定した紫の猫耳、ロングヘア、紫の瞳、黒×紫衣装のゆずちゃん。参加キャラはこの画風を参照するが、猫耳・衣装・顔などを他キャラへ移植しない。

## 1. 画像と紹介情報を受け付ける

初期は個別相談で受付。応募フォームは後からでよい。

| 受け取るもの | 内容 |
| --- | --- |
| 元画像 | 写真・イラスト・動物・マスコット・手描きなど。対象が複数なら誰かを指定 |
| 表示名 | ゲーム内で公開する名前 |
| 参加区分 | 出場者／応援参加／創作キャラなど。一般参加を出場者と誤認させない |
| 紹介 | 短い紹介文、所属・活動名は任意 |
| Xリンク | 希望する本人・活動アカウントのURL。未提供なら空欄のまま、推測しない |
| 残す特徴 | 髪・耳・色・衣装・アクセサリーなど |
| 補完の希望 | 見切れた服や足などの希望。重要な不明点だけ確認 |
| 了承 | キャラ化・ゲーム掲載・名前と紹介とXリンクの公開・結果画像への使用範囲 |

第三者の推薦だけで制作・掲載しない。人物のキャラ化は制作前に本人の了承を確認し、画像・創作キャラの利用は必要な権利者の了承も確認する。最終デザインは公開前に確認してもらう。生成や確認に必要な画像以外の個人情報は集めない。

## 2. 管理IDを付ける

受付時に固定IDを採番する。例：char_0001。表示名・Xアカウントが変わってもIDは変えない。

1キャラ1行の管理台帳に、ID、表示名、区分、紹介、所属、Xリンク、担当、受付日、制作了承日、了承範囲、最終画像確認日、公開状態、採用版、更新日、素材の保存先を記録する。連絡先・了承記録・元写真は運営用で、公開データに含めない。

状態：受付 → 了承確認待ち → 制作中 → 本人確認待ち → 登録準備 → 公開中。必要に応じて保留・非公開・取り下げ。

## 3. 基本キャラを1体制作する

応募画像＋ゆずちゃんの画風見本＋残す特徴のメモを使う。元画像の識別要素を優先する。人物はデフォルメし、人外キャラは元の形を尊重。全身が不明な場合は必要な補完を行い、推測した箇所を確認時に伝える。

制作マスターの目標：1024×1024px、背景透過PNG、文字・ロゴ・床・台座・独立した背景演出なし。耳・髪・手・靴まで収め、周囲に余白を残す。現在の確定ゆずちゃんは承認済みデザインを優先し、サイズ規格のためだけに描き直さない。

公開前に、本人らしさ、衣装・配色、手足、見切れ、実際の透過、小サイズでの判別を確認する。アルファチャンネルがあるだけでは合格にせず、明暗両方の背景に重ね、背景残り・半透明の衣装や髪・色の縁取りも見る。

## 4. 共通キャラシートを整える

各キャラに管理用シートを作る。最初は採用基本画像と、名前・特徴・主要色・変更しない点だけでよい。リアクションができたら同じシートへ追加する。三面図は必須にしない。

| 素材キー | 用途 | 制作方針 |
| --- | --- | --- |
| idle | 通常・待機 | 基準となる姿勢・表情 |
| hit | 成功 | 笑顔・ウインクなど、控えめな変化 |
| combo | PERFECT連続・コンボ節目 | 分かりやすい喜び |
| miss | ミス | 軽い驚き。強い落胆や責める表現にしない |
| cheer | 応援・立て直し | 前向きな励まし |
| clear | クリア・結果 | 大きめの喜びのポーズも可 |

プレイ中のidle／hit／combo／miss／cheerは、頭の位置・体の大きさ・向き・接地位置をなるべく固定する。画像切替でキャラが跳ねないことを優先。clearのみ大きくポーズを変えてよい。人外キャラは顔や手の有無に合わせて同じ感情を表現する。

6種類すべてを登録条件にしない。差分が未制作ならidleで代用し、共通の光・小さな動きで反応を補う。毎タップで全身画像を切り替えず、反応の表示時間・優先順位は実機で調整する。

今回生成した6ポーズは候補資料。ユーザーの想定と異なる点があり、全員の強制テンプレート・実装承認済み素材として扱わない。確定済み基本ゆずちゃんを元に整える。

## 5. 本人・権利者に最終確認してもらう

基本画像、できている差分、表示名、紹介、区分、Xリンク、利用範囲を一緒に確認してもらう。修正があれば同じID内で版を増やす。了承が取れた画像・情報だけを登録準備へ進める。

## 6. ゲーム用素材を登録する

元画像、制作途中、承認済みマスター、ゲーム用出力、確認用シートを分ける。元画像と旧版を上書きしない。

フォルダ例：char_0001/source、drafts、approved/v001、runtime/v001、review。

ゲーム用画像はキャラごとに同じ透明キャンバスと基準位置で出力し、idle.png、hit.png、combo.png、miss.png、cheer.png、clear.pngの共通名を使う。表示用サイズは実機確認で調整可能とし、マスターは残す。シートは確認用、実際のゲームには個別PNGを登録する。

実装側の公開データにはID、名前、区分、紹介、任意の所属、Xリンク、各画像の参照、表示位置・倍率、公開フラグ、素材版を持たせる。画像不足時はidleへ戻す。元写真・了承記録は公開しない。

キャラ選択画面で誰かを確認でき、プレイ中は選択キャラと名前を表示。紹介や外部リンクは選択・結果画面に配置し、ノーツの視認性を守る。全曲で選択可能とする。

## 7. 公開前に確認する

- 本人・権利者の了承と最終画像確認が記録されている。
- 名前・所属・参加区分・Xリンクが正しい。
- 透過、見切れ、輪郭、キャラの大きさ・切替位置が自然。
- 実際のスマホ表示で識別でき、4レーンを隠さない。
- 差分がなくても表示でき、画像読込失敗時も操作不能にならない。
- キャラを替えても譜面・判定・スコアが変わらない。

## 8. 更新・取り下げ

名前・紹介・Xリンクだけなら画像を再生成せず更新。衣装や画像の変更は新しい版として確認・差し替えし、IDを維持する。過去の曲・難易度別自己ベストはキャラ変更と切り離す。

取り下げはまずサイトの一覧・プレイ・結果画面から非公開にする。保存済み選択も検証し、非公開キャラならゆずちゃんに戻す。公開素材の配信停止やキャッシュ更新も対応する。既に他の人が保存・投稿した結果画像まで自動回収できるとは約束しない。

## 引継ぎメモ

初期は台帳＋運営による手動登録で十分。自動生成、管理画面、応募フォームは後回し。全キャラで共通データ構造と素材キーを使い、追加のたびにゲーム本体を書き換えない構成にする。キャラ追加で制作が止まらないよう「基本画像1枚で登録可能、差分は段階追加」を守る。
